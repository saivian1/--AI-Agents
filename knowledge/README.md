# 知识库目录

本目录包含用于演示智能体功能的示例文档。

## ⚠️ 重要声明

**所有文档均为虚构内容，仅用于演示AI智能体功能！**

- ✅ 文档中的数据、设备型号、故障案例均为虚构
- ✅ 不代表任何真实设备或实际运维经验
- ✅ 实际操作请严格遵循设备制造商的官方文档

## 目录结构

```
knowledge/
├── documents/          # 通用技术文档
│   ├── fault_cases.txt           # 故障案例库（示例）
│   └── maintenance_guide.txt     # 维护指南（示例）
│
├── regulations/        # 规程标准文档
│   └── operation_manual.txt      # 操作规程（示例）
│
└── reports/           # 报告模板
    └── README.md                 # 本文件
```

## 支持的文件格式

智能体系统支持以下文档格式：

- **PDF** (`.pdf`) - 推荐用于正式文档
- **Word** (`.docx`, `.doc`) - 适合编辑的文档
- **文本** (`.txt`) - 轻量级纯文本文档

## 如何添加自己的文档

### 步骤1: 准备文档

确保您的文档：
1. 已完全脱敏，不含敏感信息
2. 内容清晰，结构合理
3. 使用支持的文件格式

### 步骤2: 放置文档

将文档放入相应的子目录：

```bash
# 技术文档
cp your_document.pdf knowledge/documents/

# 规程文档
cp your_regulation.pdf knowledge/regulations/

# 报告模板
cp your_report_template.txt knowledge/reports/
```

### 步骤3: 加载到知识库

```python
from core.knowledge_base import create_knowledge_base

kb = create_knowledge_base()
kb.add_from_directory("knowledge")
```

系统会自动：
- 扫描所有子目录
- 加载支持格式的文档
- 分块处理文本
- 生成向量嵌入
- 存储到向量数据库

## 文档编写建议

### 结构化内容

使用清晰的层级结构：

```markdown
# 一级标题 - 文档主题

## 二级标题 - 主要章节

### 三级标题 - 具体内容

正文内容...
```

### 关键信息突出

- 使用**加粗**强调重要概念
- 使用列表组织要点
- 添加示例和案例

### 专业术语一致

- 统一使用行业标准术语
- 首次出现时可加注释
- 避免使用缩写除非已说明

## 知识库优化技巧

### 1. 文档长度适中

- 单个文档建议 5-50 页
- 过长的文档会被自动分块
- 可考虑拆分成多个主题文档

### 2. 内容相关性

- 同一主题的内容放在一起
- 避免在单个文档中混杂过多主题
- 使用子目录组织不同类别

### 3. 定期更新

- 及时添加新的经验和案例
- 删除过时或不准确的内容
- 保持知识库的时效性

## 向量数据库

加载的文档会被处理并存储在向量数据库中：

- **位置**: `./chroma_db/` (可配置)
- **持久化**: 自动保存，无需重复加载
- **更新**: 添加新文档会增量更新
- **清空**: 调用 `kb.clear()` 可清空知识库

## 数据安全

### 禁止添加的内容

❌ 真实设备的序列号和型号
❌ 实际的运维数据和参数
❌ 敏感的商业信息
❌ 个人身份信息
❌ 内部机密文档

### 建议做法

✅ 使用虚构的设备编号（如"X号机组"）
✅ 使用范围值而非精确参数（如"70-80°C"）
✅ 添加免责声明
✅ 标注"示例"或"虚构"

## 常见问题

### Q: 如何知道文档已加载？

运行加载命令后会显示：
```
Added X documents from knowledge
```

### Q: 支持中文文档吗？

完全支持中文内容，无需特殊处理。

### Q: 可以加载多语言文档吗？

可以，但建议：
- 同一文档使用单一语言
- 或在文档中明确标注语言

### Q: 如何更新已有文档？

1. 修改或替换文档文件
2. 清空知识库：`kb.clear()`
3. 重新加载：`kb.add_from_directory("knowledge")`

### Q: 知识库太大怎么办？

可以：
- 使用多个collection分类存储
- 调整chunk_size减少分块数量
- 只加载必要的文档

## 技术参数

默认配置（可在 `core/config.py` 中修改）：

```python
chunk_size = 1000        # 每个文本块的字符数
chunk_overlap = 200      # 文本块之间的重叠字符数
top_k = 3               # 检索返回的文档数量
```
